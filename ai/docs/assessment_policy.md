# Assessment Anchor 정책

## 문서 상태와 목적

- 상태: 1차 초안
- 목적: 대상별 초기 자가 보고 결과를 생활·감정 변화 해석을 위한 고정
  기준점으로 저장하는 원칙을 정의한다.

Assessment Anchor는 최종 판단값이나 정답 라벨이 아니다. Re:Mind는 초기
자가 보고 결과와 이후 생성하는 생활 패턴 분석 결과를 별개의 데이터로
저장하고 화면과 API에서도 출처를 구분한다.

## 대학생 정책

- 이번 MVP에서는 팀이 설계한 자체 초기 생활 상태 설문을 사용한다.
- 자체 설문은 표준화된 심리검사가 아니다.
- 의료적 판단이나 번아웃 여부를 정하는 데 사용하지 않는다.
- 출력 차원의 예시는 `exhaustion`, `academic_burden`,
  `recovery_difficulty`다.
- 차원 이름, 실제 문항, 점수 범위, 계산 방법, 해석 문구는 팀 검토가
  끝나기 전까지 확정하지 않는다.
- 자체 문항의 버전과 응답 시각, 원본 점수, 출처를 함께 보존한다.

## 사회초년생 정책과 fallback

- K-BAT의 사용 조건, 문항 이용 범위, 결과 표시 기준을 확인 중이다.
- 확인되지 않은 사용 가능 여부나 라이선스 조건을 사실처럼 가정하지
  않는다.
- 확인 과정은 데이터 모델과 AI 인터페이스 개발을 블로킹하지 않는다.
- 1주차 종료 시점까지 사용 조건을 확인하지 못하면 사회초년생도 자체 초기
  상태 설문으로 진행한다.
- 이후 허용 범위가 확인되면 저장·분석 계약을 바꾸지 않고 교체할 수 있도록
  `assessment_type`으로 평가 종류를 분리한다.
- K-BAT를 사용하게 되더라도 AI가 원본 점수를 수정하거나 별도 점수로
  재계산하지 않는다.

K-BAT의 실제 문항은 사용 조건과 출처를 확인하기 전까지 저장소, 합성
데이터, 테스트에 복사하지 않는다.

## 공통 저장 원칙

Assessment Anchor에는 최소한 다음 정보를 함께 저장한다.

- `assessment_type`: 자체 설문과 향후 허용될 수 있는 평가 유형의 구분
- `target_group`: 대학생 또는 사회초년생 등 대상 그룹
- `completed_at`: 응답 완료 시각과 시간대
- `dimensions`: 평가 원본이 제공한 차원별 값
- `interpretation_scope`: 생활·감정 변화 해석을 위한 기준점이라는 범위
- `source`: 설문명과 버전 등 출처 식별 정보

공통 처리 원칙은 다음과 같다.

- 최초 저장한 응답과 점수는 불변 원본으로 취급한다.
- 정정이 필요하면 기존 값을 덮어쓰지 않고 정정 이력 또는 새 버전을
  남기는 방식을 백엔드에서 검토한다.
- AI는 설문 점수를 수정하거나 재계산하지 않는다.
- 결합 결과에는 필요한 요약만 전달하고, Assessment Anchor 원본과
  Re:Mind의 생활 패턴 분석 결과를 혼합 저장하지 않는다.
- Assessment Anchor는 시간에 따른 생활·감정 변화를 해석하는 고정
  기준점으로만 사용한다.
- 평가 유형이 다르면 차원 의미와 점수 범위가 다를 수 있으므로 서로 직접
  비교하지 않는다.
- 누락된 값은 숫자 `0`으로 대체하지 않는다.

## 사용자 표현 원칙

- 초기 자가 보고, 기준 정보, 생활 패턴 변화, 참고 신호처럼 역할을
  정확히 드러내는 표현을 사용한다.
- “진단”, “확정”, “치료 필요”처럼 의료적 판단으로 오해될 표현은 결과
  문구에 사용하지 않는다.
- 높은 원본 점수와 최근 생활 변화가 일치하지 않더라도 어느 한쪽을
  정답으로 간주하지 않고 서로 다른 시점과 출처의 신호로 설명한다.
