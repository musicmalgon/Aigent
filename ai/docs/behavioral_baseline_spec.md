# Behavioral Baseline 명세 초안

## 문서 상태와 범위

- 상태: 1차 초안
- 범위: 개인의 생활 기록으로 기준 구간을 요약하고 최근 구간과 비교하기
  위한 데이터 규칙
- 이번 단계: 명세만 작성하며 계산 알고리즘과 판정 임계값은 구현하지 않음

Behavioral Baseline은 집단 평균이나 의료 기준이 아니라 같은 사용자의 이전
기록을 요약한 비교 기준이다. 여기에서 언급하는 기간과 변화 기준은 MVP
실험 규칙이며 의료적 판단 기준이 아니다.

## 후보 기간

- 최소 Baseline 후보 기간: 14일
- 최근 비교 후보 기간: 7일
- 14일과 7일은 1차 MVP 실험을 시작하기 위한 기간 후보이며, 실제 데이터
  커버리지와 주중·주말 변동을 검토한 뒤 조정할 수 있다.
- Baseline 구간과 최근 비교 구간은 겹치지 않게 구성하는 것을 초기
  후보로 둔다.
- 날짜 경계는 각 `BehavioralDailyRecord.time_zone`에 저장된 IANA 시간대를
  기준으로 계산한다. 프로필의 현재 시간대로 과거 날짜를 다시 해석하지
  않는다.
- 이동 또는 DST로 시간대가 바뀌면 각 레코드에 실제 집계에 사용한 시간대를
  보존한다. 시간대 변경 시 한 활동 구간을 어느 날짜에 귀속할지는 백엔드
  수집 정책에서 버전으로 관리할 `TODO`다.

## 유효 기록 일수

유효 일수는 지표별로 계산한다. 특정 날짜에 수면 값이 유효하더라도 걸음
수 값이 없을 수 있으므로 하나의 전체 유효 여부로 모든 지표를 대신하지
않는다.

`BehavioralBaseline`은 다음 두 종류의 유효 일수를 함께 보존한다.

- `valid_days`: Baseline 기간 중 하나 이상의 행동 데이터가 존재한 날짜 수
- `valid_days_by_metric`: `BaselineMetric`별 유효 날짜 수
- `calculation_version`: 집계 정책과 구현을 재현하기 위한 명시적 버전

지표별 충분도는 `sufficiency_by_metric`에 저장한다.

현재 `BaselineMetric` 키는 자유 문자열이 아니라 다음 여덟 값으로
제한한다.

- `sleep_minutes`
- `steps`
- `active_minutes`
- `exercise_minutes`
- `work_or_study_minutes`
- `rest_minutes`
- `schedule_count`
- `subjective_fatigue`

- `sufficient`: 해당 지표를 분석할 수 있다고 버전별 정책이 판단한 상태
- `partial`: 값은 있으나 안정적인 비교에는 부족한 상태
- `insufficient`: 분석 기준에 미달한 상태
- `unavailable`: 해당 지표의 유효 값이 없고 유효 일수가 `0`인 상태

지표별 최소 유효 일수는 아직 확정하지 않는다. 전체 결과의
`minimum_required_days`를 모든 지표에 자동 적용하거나, 하나의 지표 상태로
전체 `data_sufficiency`를 임의 결정하지 않는다. 이 정책은 실제 커버리지
검토 후 버전으로 관리할 `TODO`다.

지표별 유효 기록의 초기 정의는 다음과 같다.

1. 날짜가 유효한 ISO 날짜이고 중복되지 않는다.
2. 해당 지표의 값이 `null`이 아니다.
3. `coverage`가 `unavailable`이 아니다.
4. 값이 명세의 물리적 범위 안에 있다.
5. 값 `0`은 관측된 값일 수 있으므로 결측으로 바꾸지 않는다.

부분 커버리지의 값을 유효 일수에 포함할지는 지표와 수집 방식별 품질
검토가 필요하다. 지표별 최소 유효 일수는 아직 확정하지 않으며 `TODO`로
남긴다. 캘린더상 14일을 확보했더라도 필요한 지표의 유효 기록이 부족하면
`data_sufficiency=insufficient`로 처리해야 한다.

중복 날짜가 있으면 임의로 합치지 않고 출처, 수집 시각, 수정 이력을
확인한다. 일 단위 집계 규칙은 백엔드 수집 계약과 함께 확정한다.

## 저장할 요약값

각 지표에 대해 다음 값을 함께 검토한다.

- 평균: 전체 수준의 변화를 보기 쉽지만 일부 큰 값의 영향을 받을 수 있다.
- 중앙값: 일시적인 큰 값의 영향을 줄이고 평소 수준을 설명하는 데
  유용하다.
- 유효 일수: 요약값이 몇 개의 기록을 바탕으로 하는지 보여 준다.
- 분포 또는 변동성 요약: 필요성은 추후 실제 합성·검토 데이터로 평가한다.

평균과 중앙값이 크게 다르면 어느 하나를 임의로 정답으로 선택하지 않고
이상값, 부분 커버리지, 주중·주말 차이를 검토한다.

## 평일·주말 분리

- `weekday_averages`와 `weekend_averages`를 별도로 저장할 수 있게 한다.
- 14일 후보 기간은 보통 두 번의 주중·주말을 포함하지만, 각 그룹의 유효
  일수가 충분한지는 별도로 확인한다.
- 국가별 공휴일, 교대 근무, 개인별 근무일을 단순한 토·일 구분에 반영할지
  여부는 `TODO`다.
- 그룹별 데이터가 부족하면 전체 요약값은 유지할 수 있으나 부족한 그룹의
  값은 `null`로 두고 근거 없는 `0`을 넣지 않는다.

## 비교 지표와 변화량

1차 비교 후보 지표는 다음과 같다.

- 수면 시간(`sleep_minutes`)
- 걸음 수(`steps`)
- 활동 시간(`active_minutes`)
- 휴식 시간(`rest_minutes`)

각 지표는 Baseline 요약과 최근 7일 요약의 절대 변화량을 우선 계산하는
것을 초기 후보로 둔다. 비율 변화는 Baseline 값이 `0`일 때 정의할 수
없으므로 별도 처리해야 한다. 비율을 사용할지와 의미 있는 변화로 볼
최소값은 검토 전이며 `TODO`다.

운동 시간, 일·학업 시간, 일정 수, 주관적 피로는 주요 변화의 맥락을
보조하는 후보 지표다. 이 지표들의 결합 방식과 우선순위는 아직 정하지
않는다.

## 하루 변화와 지속 변화

- 하루만 달라진 경우와 여러 유효 일에 걸쳐 이어진 경우를 구분한다.
- `duration_days`는 실제 관측이 연속된 유효 일수에 근거해야 한다.
- 결측 날짜를 변화가 이어진 날로 간주하지 않는다.
- 단일 날짜 변화는 원인을 확인할 관찰 신호로 남기되, 지속 변화와 같은
  수준으로 취급하지 않는 것을 초기 후보로 둔다.
- 며칠을 “지속”으로 볼지, 중간의 하루 회복이나 결측을 어떻게 처리할지는
  실제 검토 데이터로 정할 `TODO`다.

`PatternChangeResult`에서 충분한 데이터로 두드러진 변화가 관찰되지 않은
상태는 `change_level=no_notable_change`, `duration_days=0`, 빈 `factors`로
표현한다. 여기서 `0`은 변화 지속일이 관찰되지 않았다는 계약값이며 결측과
다르다. 데이터가 부족하거나 미가용하면 `change_level=unknown`,
`duration_days=null`, 빈 `factors`를 사용한다. `change_observed`는
`duration_days>=1`과 하나 이상의 factor가 있을 때만 허용한다.

## 데이터 부족 처리

다음 상황은 지표별 또는 전체 `data_sufficiency`에 반영한다.

- Baseline 후보 기간이 14일보다 짧음
- 지표별 유효 기록 일수가 검토 후 정할 최소 요건에 미달함
- 최근 비교 후보 기간의 유효 기록이 부족함
- 날짜 중복, 잘못된 범위, 출처 불명 등으로 기록을 신뢰하기 어려움

데이터가 부족하면 변화 없음으로 해석하지 않는다. 변화량은 `null`로 두고
부족한 지표와 기간을 명시한다. 숫자 `0`은 실제 관측된 0일 때만
사용한다.

## 건강 데이터 미연동

- 건강 데이터 연결을 하지 않았거나 사용할 수 없으면 해당 지표 값은
  `null`, 커버리지는 `unavailable`로 기록한다.
- 연결 거부, 기술적 오류, 아직 수집되지 않음은 가능한 경우 별도의 출처
  메타데이터나 누락 사유로 구분한다.
- 미연동을 걸음 수 또는 활동 시간 `0`으로 바꾸지 않는다.
- 건강 데이터가 없어도 수동 생활 기록과 감정 일기는 독립적으로 처리할
  수 있으나, 없는 지표에 대한 변화는 생성하지 않는다.

## 자동 데이터와 수동 입력 충돌

다음은 확정 정책이 아닌 초기 후보이다.

1. 두 값을 모두 원본과 출처별로 보존하고 조용히 덮어쓰지 않는다.
2. 자동 수집의 시간 범위와 수동 입력의 의미가 같은지 먼저 확인한다.
3. 같은 의미라면 기기 커버리지, 수정 시각, 사용자 명시적 정정 여부를
   바탕으로 대표값을 선택한다.
4. 사용자가 명시적으로 정정한 값을 우선할지, 자동값과 병렬 표시할지는
   제품·백엔드 팀 검토 후 확정한다.
5. 선택된 대표값에는 사용한 출처와 계산 버전을 남긴다.

자동 데이터 우선 또는 수동 데이터 우선이라는 단일 규칙은 아직 확정하지
않는다.

## 계산 결과에 필요한 추적 정보

- Baseline 시작일과 종료일
- 지표별 유효 일수와 전체 후보 기간
- 최소 필요 일수의 적용 버전
- 평균, 중앙값, 평일·주말 요약
- 사용한 원본 레코드 또는 재현 가능한 참조
- 제외된 날짜와 제외 사유
- 계산 버전

## 미확정 항목과 TODO

- 부분 커버리지의 지표별 유효 처리
- 지표별 최소 유효 일수
- 변화량 계산에 평균과 중앙값을 결합하는 방식
- 의미 있는 변화와 지속 기간의 초기 임계값
- 공휴일, 교대 근무, 시간대 변경 처리
- 자동·수동 데이터 충돌 시 최종 우선순위
- 이상값 탐지와 제외 절차
- 최근 비교 구간 중 결측일 처리

이 TODO를 확정할 때도 결과는 개인 생활 패턴의 관찰 신호로만 설명하고
의료적 기준이나 확률로 표현하지 않는다.
