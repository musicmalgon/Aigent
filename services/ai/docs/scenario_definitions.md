# 합성 생활 데이터 시나리오 정의

## 공통 원칙

`ai/data/synthetic/synthetic_daily_records.csv`의 모든 행은 테스트만을 위해
만든 합성 기록이다. 실제 사용자, 계정, 기기 또는 건강 데이터에서 가져온
값이 아니다.

- `user_id`는 사람 식별자가 아니라 시나리오 이름이다.
- `sleep_source`와 `steps_source`의 `synthetic` 값이 합성 출처임을
  표시한다. 값이 비어 있는 행에서도 이는 실제 측정 출처가 아니라 fixture
  자체의 합성 출처를 뜻한다.
- `coverage=complete`는 해당 합성 행의 주요 값이 채워졌음을,
  `partial`은 일부 지표가 없거나 하루 수집 구간이 불완전함을,
  `unavailable`은 해당 일자의 수치 값이 없음을 뜻한다. 따라서 `partial`
  행은 모든 지표 값이 있더라도 하루 전체를 대표한다고 가정하지 않는다.
- 빈 셀은 값이 없다는 뜻이다. 관측된 숫자 `0`과 구분한다.
- `time_zone`은 각 합성 날짜를 산출할 때 사용한 IANA 식별자다. 현재
  fixture는 모두 `Asia/Seoul`이지만 운영 기본값이나 사용자 위치를
  의미하지 않는다.
- 수치는 알고리즘 임계값이나 실제 사용자 분포를 나타내지 않으며 시나리오
  동작을 검증하기 위한 예시다.
- `subjective_fatigue`의 1~5 값은 이 파일 안에서만 쓰는 합성 예시 척도다.
  제품 척도와 해석 문구는 확정 전이다.
- 분 단위 값, 걸음 수와 일정 수는 정수로 기록한다. 소수 값은 현재 fixture
  계약에 포함하지 않는다.

## 1. `stable_user`

- 기간: 2026-01-01 ~ 2026-01-14, 14일
- 유효 기록: 14일의 `complete` 합성 기록
- 의도: 수면, 걸음 수, 활동 시간과 휴식 시간이 일상적인 범위 안에서
  오르내리지만 한 방향으로 계속 감소하지 않는 예시
- 기대 처리: 최소 Baseline 후보 기간을 충족한다. 안정 여부를 가르는
  수치 임계값은 아직 적용하지 않는다.
- fixture 검증: 주요 네 지표 각각에 증가일과 감소일이 모두 있고, 14일
  전체가 한 방향으로 단조 변화하지 않는지 확인한다. 또한 첫 7일의 관측
  범위를 이 fixture 자체의 비교 범위로 삼아 최근 7일 수면·걸음 수·휴식
  시간 평균이 그 최솟값과 최댓값 사이인지, 최근 7일 합성 주관적 피로
  평균이 첫 7일의 최댓값을 넘지 않는지 확인한다. 이는 고정 수치나 운영
  임계값이 아니라 stable fixture가 자체 초기 구간에서 과도하게 이탈하지
  않았음을 검증하는 상대 조건이다.

이 시나리오는 “변화가 없음”을 의료적 또는 절대적 상태로 정의하지 않는다.
합성 기간 안에서 뚜렷한 지속 감소 패턴을 넣지 않았다는 뜻이다.

## 2. `worsening_user`

- 기간: 2026-02-01 ~ 2026-02-21, 21일
- 앞 기간: 2026-02-01 ~ 2026-02-14의 비교적 일정한 14일 기록
- 최근 기간: 2026-02-15 ~ 2026-02-21의 7일 기록
- 의도: 최근 7일에 수면, 걸음 수, 활동 시간, 휴식 시간이 단계적으로
  감소하고 주관적 피로 예시 값이 높아지는 패턴
- 감정 조건: 향후 연결할 합성 일기에서는 `fatigue` 또는 `anxiety`
  경향을 사용한다. 현재 생활 CSV에는 감정 필드가 없으므로 이 조건은
  시나리오 메타데이터이며 결합 테스트용 일기 연결은 `TODO`다.
- 기대 처리: 앞 14일로 Baseline을 만들고 최근 7일과 비교할 수 있다.
  어느 변화량부터 의미 있다고 볼지는 아직 확정하지 않는다.
- fixture 검증: 앞 14일과 최근 7일이 연속된 `complete` 행인지, 최근 7일의
  네 주요 지표가 예시 설계대로 단계적으로 감소하는지, 합성 주관적 피로
  값이 단계적으로 증가하는지만 확인한다. 이 형태는 운영 규칙이나 사용자
  판정 기준이 아니다.

이 시나리오 이름은 최근 생활 패턴이 기준 구간보다 낮아지는 합성 구조를
뜻할 뿐, 사람의 상태에 대한 의료적 판단을 뜻하지 않는다.

## 3. `insufficient_user`

- 기간: 2026-03-01 ~ 2026-03-07, 7일
- 기록 구성: `complete`, `partial`, `unavailable`을 섞고 빈 셀을 포함
- 의도: 캘린더 기간 자체가 최소 Baseline 후보 14일보다 짧고 유효 값도
  일부 누락된 상태
- 기대 처리: Baseline 생성 불가 사유를 데이터 부족으로 반환한다. 누락
  값을 숫자 `0`으로 보정하지 않는다.
- fixture 검증: 7일이 연속되어도 최소 후보 기간보다 짧고,
  `complete`·`partial`·`unavailable`이 모두 존재하며 `unavailable` 행의
  모든 수치가 비어 있는지 확인한다.

## 컬럼과 단위

| 컬럼 | 의미 | 단위 또는 값 |
|---|---|---|
| `user_id` | 합성 시나리오 식별자 | 세 시나리오 이름 중 하나 |
| `date` | 합성 기록 날짜 | ISO `YYYY-MM-DD` |
| `time_zone` | 합성 날짜 경계 산출에 사용한 시간대 | IANA 식별자 |
| `sleep_minutes` | 수면 시간 | 분, `0..1440` 또는 빈 값 |
| `steps` | 걸음 수 | 회, 0 이상 또는 빈 값 |
| `active_minutes` | 활동 시간 | 분, 0 이상 또는 빈 값 |
| `exercise_minutes` | 운동 시간 | 분, 0 이상 또는 빈 값 |
| `work_or_study_minutes` | 일·학업 시간 | 분, 0 이상 또는 빈 값 |
| `rest_minutes` | 휴식 시간 | 분, 0 이상 또는 빈 값 |
| `schedule_count` | 일정 수 | 개, 0 이상 또는 빈 값 |
| `subjective_fatigue` | 합성 주관적 피로 예시 | 1~5 예시값 또는 빈 값 |
| `sleep_source` | 수면 값의 fixture 출처 | `synthetic` |
| `steps_source` | 걸음 수 값의 fixture 출처 | `synthetic` |
| `coverage` | 행 단위 가용성 요약 | `complete`, `partial`, `unavailable` |

`coverage`는 현재 CSV 검증용 요약 필드다. 실제 API에서는 지표별
`coverage_by_field`를 사용해 서로 다른 가용성을 보존해야 한다.

이 문서에 적은 단조 증가·감소와 1~5 범위는 현재 합성 fixture가 의도대로
유지되는지 확인하는 데이터 계약이다. 실제 사용자의 변화 여부를 정하는
임계값이나 의료 기준으로 재사용하지 않는다.
